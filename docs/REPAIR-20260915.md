# RTK / CCE integration repair — 2026-09-15

Local repair of beta.2; not a new GitHub release. The installed Python package
was updated after a backup at
`%LOCALAPPDATA%/CodexTokenSaver/backups/repair-20260915-rtk-cce`.
Existing MCP processes need a new Codex session to load the repaired code.

## Changes

- RTK inherits the actual shell working directory. A normalized hook input
  without `workdir` no longer forces the command into the session directory.
  Accounting stays with the session project, including non-Git subdirectories.
  The Windows wrapper propagates the child exit code explicitly.
- The opened folder defines project identity; an ancestor Git checkout no longer
  silently widens the CCE index scope.
- CCE's pinned indexing pipeline runs on a separate event loop thread. Its
  synchronous model initialization and embedding no longer block the MCP loop.
  A project-local file lock serializes indexing between processes. Index state
  reports distinguish empty, indexing, failed and completed-with-errors states.
- The proxy bounds tool requests to 45 seconds (below the host's 60-second
  deadline), removes cancelled requests, and discards late replies. Forwarding
  to the pipe is explicitly distinct from receipt in a native session. Only a
  matching successful native response can credit a CCE observation.
- Session snapshots ingest CCE invocation events as well as measured pairs.
  CLI/dashboard expose calls, failures, timeouts and unmeasured outcomes.
- Hook diagnostics record input field names and the last rewrite decision,
  without command contents. RTK execution writes a start marker with cwd.
  Pending rewrites are visible; empty unconfirmed spools are reclaimed only
  after session end, with a diagnostic retained. Started/incomplete spools are
  retained rather than deleting a potentially running command's data.
- PostToolUse imports RTK spools without reparsing the entire native transcript.
  `status` says `installed`, not `ready`. `doctor --json` now exposes
  `installation_ready` instead of `ready`, with explicit installation-only scope
  and the last project health record. Health files are historical and may belong
  to another MCP process; the selected session's events remain authoritative.

## Remaining limits

This does not make every command eligible for RTK, guarantee positive savings,
or override native hook/tool approvals. Synchronous CCE retrieval itself can
still exceed the bounded request deadline; indexing responsiveness is improved,
not a guarantee that arbitrary repositories finish indexing within 60 seconds.
Old running MCP processes keep their old code until restarted. GitHub release
archives have not been replaced by this local repair.
